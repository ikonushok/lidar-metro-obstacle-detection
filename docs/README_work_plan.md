## Текущая разработка алгоритма

Статусы уточнены пользователем 2026-09-23:

1. **В работе:** генератор синтетических препятствий и фильтр ложных срабатываний.
2. **Затем:** подготовка frozen synthetic dataset, point-level labels, split и baseline-прогона `candidate_baseline_v2` по [финальному плану обучения](stages/stage_5/stage_5_synthetic_model_training_plan.md). Синтетика дополняет реальные данные, но не является независимым полевым тестом. Исходные проезды для генерации и варианты одного сценария нужно учитывать при разделении обучения и проверки, чтобы не смешать производные одного входа.
3. **Затем:** сравнение нескольких кандидатов на одинаковых данных: `candidate_baseline_v2 + temporal`, `decision_tree + temporal`, `random_forest + temporal`, `gradient_boosting + temporal`, `lightgbm + temporal` при доступности зависимости и `ensemble_v1 + temporal`. Выбор требует held-out результата, real-regression, runtime-совместимого causal temporal и overlap-анализа FP/TP/FN; смена модели не обязательна сама по себе.
4. **После обучения и выбранной доработки:** обновление модели в общем C++ ядре уже существующих direct/ROS2 адаптеров, проверка соответствия обученному артефакту и подготовка сдачи по списку ниже. Оба способа запуска реализованы; речь не о повторном создании интерфейсов.

**Условие обновления модели:** сохранить прямой C++ путь текущего плеера (`runtime_transport=direct_cpp`), один активный фильтр и отдельный ROS2-вход. Возврат ROS2-транспорта в плеер не входит в эту работу. После обучения сравнить скорость текущей и новой моделей на одинаковом прямом пути по [программе проверки](README_noise_classifier.md#сохранение-прямого-пути-плеера-при-обновлении-модели); ускорение или отсутствие замедления заранее не утверждается.

Эти работы не запускаются повторно в данной задаче документации. Ранее записанное «генератор отложен» заменено этим уточнением.

## Дальнейшие задачи и условия их запуска

- Адресная доработка FP/FN/UNKNOWN — по конкретным случаям: видимость → ось → membership → компонента → модель. Сравнивать до/после на одинаковых кадрах и конфигурации; сохранять raw evidence. Не дублировать текущие параллельные работы.
- Первая адресная UNKNOWN-доработка завершена для `AMBIGUOUS_LOCAL_CONTINUITY_PATH`: на development seven-source `UNKNOWN_FP` снижен с 193 до 41 без изменения runtime ML-модели и без перевода `UNKNOWN` в `CLEAR`. Оставшиеся `41 UNKNOWN_FP` требуют визуального/held-out review и не должны использоваться как hard-negative для component classifier.
- Независимые положительные проезды, срезы дальность/размер/поворот, event matching и первое/устойчивое обнаружение остаются задачами оценки. Существующие frame-метрики их не заменяют. Не смешивать FP-кадры/мин с FP-событиями/мин.
- Генератор и фильтр ложных срабатываний находятся в разработке; обучение на синтетике следует после подготовки данных. План этой задачи не подменяет работу параллельных сессий и не утверждает, что новая модель уже проверена.
- Таймеры stream CLI исправлены отдельной runtime-правкой: обычный запуск считает один активный фильтр, `--compare-noise-filters` оставлен для диагностического evaluator-а, lean model benchmark пересчитан. Основание дефекта B01 сохранено как исторический аудит: [bug-audit](reports/project-readiness/lidar-mosmetro3d-all-markdown-2026-09-23/bug-audit-2026-09-23.md). Остаётся не stream-fix, а full-path проверка ROS2/HTTP/UI с очередью, drops и целевым стендом.
- Подробный профиль cold/warm/seek и deadline/recovery worker отложены до отдельной задачи при необходимости. Отсутствие deadline в коде не доказывает фактического зависания плеера.
- Перед итоговой сдачей нужны проверка потока/нагрузки/ошибок входа, latency/queue/drops/RAM/CPU на указанном оборудовании и материалы демонстрации. Их объём согласуется после п. 3; видео и таблицы должны относиться к одной версии.

План не разрешает автоматически менять модель, thresholds, геометрию или диагностический контракт.

## Необязательные направления

Одна группировка CORE для признаков/модели, индекс соседей и переиспользование компонентов — гипотезы оптимизации после профиля. Arc/hidden-tail/union — отдельная оценка пути, не доказательство obstacle recall. CUDA включать после проверки GPU runtime и full-path выигрыша. Карта, deskew, tracking и TTC требуют необходимых входов и измеримого эффекта; не блокируют текущий покадровый tangent baseline.

Это задачи завершения и подтверждения результата, а не требование заново строить уже существующие компоненты. Независимые положительные данные желательно получить для проверки обобщения; если их нет, ограничение указывается явно. Карта, tracking, TTC, CUDA и смена ML-модели не являются обязательными функциями ТЗ.

- UNKNOWN/DEGRADED не CLEAR. Synthetic tangent не наблюдаемая рельсовая опора. Source distance не расстояние от носа поезда.
- Frame/оси/единицы, mounting, профиль/margin и правила фильтра — защищённые контракты. Их нельзя менять редактурой текста или подбором на test.
- Bag/header/per-point clocks не смешиваются без проверенной связи; вычисления измеряются monotonic clock.
- CPU, Ubuntu 22.04 + ROS 2 Humble + Docker — основной путь сдачи. Локальная машина не эквивалентна стенду организатора.
- README, архитектура/алгоритм/ограничения, воспроизводимый контейнер и исходники, результаты экспериментов, короткое видео и демонстрация на контрольном bag остаются материалами сдачи. Плеер — средство демонстрации, не обязательный интерфейс автоматической проверки.

Основание статусов: code trace и датированные отчёты по ссылкам. Эта сводка не присваивает новый runtime L3/L4; уровень/команду хранить в отчёте конкретной проверки. Остаточный риск — один положительный объект, assumed geometry и смешение версий метрик.
