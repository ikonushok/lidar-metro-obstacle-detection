# Оценка переносимости решения на новый датасет

Дата оценки: 2026-09-29.

**Решение расширяемое, но заметно специализировано под доступные данные. Признаки переобучения есть — и в ML-модели, и в ручных правилах.** На скрытом датасете я ожидаю неоднородное качество: крупные привычные объекты обнаруживаются увереннее, небольшие, тонкие и необычно расположенные — существенно менее надёжно.

Это оценка текущего кода и сохранённой модели. Новый replay и обучение я не запускал.

**Насколько оно гибкое**

Архитектурно — достаточно: общее C++ ядро, отдельные direct/ROS2-входы, настраиваемые профиль, топик и часть геометрических параметров. Ось пути извлекается из облака, заранее подготовленная карта конкретного тоннеля не нужна.

Алгоритмически гибкость ограничена:

- Направление движения предполагается вдоль `−Y`; смена `source_frame` не адаптирует монтаж лидара.
- Радиус связности **0,25 м** и сильный порог **1000 точек** зависят от плотности облака и дальности.
- Часть правил зашита в C++, поэтому адаптация требует изменения алгоритма и повторной проверки.
- Продолжение оси по касательной чувствительно к поворотам и недостаточной видимости рельсов.

**Главные признаки переобучения**

1. **Положительные примеры практически из одного события.** В [метаданных модели (строка 983)](../models/baseline_v3_runtime_policy.json#L983) указаны 52 положительные компоненты из `doubleT_obstacle`. Этот же источник использован для калибровки порога. Это наблюдения известного препятствия, а не 52 независимых объекта.
2. **Модель выучила узкие признаки сцены.** Например, одно дерево даёт положительный ответ только при объёме примерно **0,24–0,99 м³** и дальности **55,02–56,64 м**. Другие используют узкие границы ширины и высоты. Это сильный сигнал специализации. Впрочем, одно дерево не определяет весь лес, а лес — весь алгоритм. [Код модели (строка 5)](../src/cpp/baseline_v3_assist_model.inc#L5).
3. **Ручная альтернативная ветка тоже ограничивает формы.** Она ищет компоненты, похожие на куб или панель, требует ≥80 точек, дальность **больше 7 м** и три последовательных кадра. Поэтому она помогает обходить ограничения модели, но не обеспечивает универсальность.
4. **Boundary-правила могут подавить настоящее препятствие.** Они применяются к компонентам уже внутри CORE и используют абсолютные координаты и размеры. Даже ≥1000 точек не отменяют это исключение. Это конкретный риск пропуска, пока без отдельного воспроизведения. [Правила (строка 241)](../src/cpp/curve_envelope_core.cpp#L241).

**Почему хорошие текущие метрики не снимают опасения**

`51/52` — результат на кадрах знакомого положительного события. Остальные реальные источники использовались для подбора сложных отрицательных примеров.

Синтетические `6/6` означают наличие **любого срабатывания в заданных временных окнах**, без проверки пространственного совпадения с объектом. Тонкий свисающий объект исключён из оценки; низкий длинный объект имеет противоречивый статус разметки. Поэтому эти числа не доказывают полноту обнаружения новых объектов.

**Прогноз для проверяющего**

| Новый набор | Мой прогноз |
| --- | --- |
| Похожий сенсор и монтаж, хорошо видимые рельсы, крупное препятствие в центре | Наиболее благоприятный сценарий |
| Кубы/панели знакомых размеров, достаточно точек и кадров | Вероятно обнаружение, иногда с задержкой |
| Тонкие, низкие, вытянутые или разреженные объекты | Повышенный риск пропуска либо `UNKNOWN` |
| Другой монтаж, сильные повороты, стрелки, закрытые рельсы | Риск ошибок габарита, ложных тревог и потери результата |
| Новый тип инфраструктуры и фоновых отражений | Возможен рост ложных тревог |

**Я бы не обещал сохранение текущего recall на скрытом наборе.** Оснований назначить честный процент успешности нет. Самая полезная следующая проверка — целый независимый проезд с новыми размеченными препятствиями, замороженными порогами и оценкой по размерам/дальности, FP/мин и доле `UNKNOWN`.

Подробности сохранил в [отчёте](../artefacts/task_specs/generalization_review/index.md). Код и параметры не менял.

Примечание: подробный отчёт — локальный артефакт в ignored-каталоге `artefacts/`, он не входит в Git и доступен только в рабочей копии, где проводилась оценка.
