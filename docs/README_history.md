# История, эксперименты и справочные материалы

Статус: навигация по датированным материалам, 2026-09-23. [Актуальный запуск](../README.md), [текущий план](README_work_plan.md), [выполненная редактура D0–D3](stages/stage_5/stage_5_documentation_d0_d3.md).

История сохраняет исходные команды, ошибки, результаты и границы проверок. «Текущий» внутри исторического текста означает состояние на дату этого текста. Для нового запуска используйте корневой README. Исследовательский эксперимент не включается в default только потому, что его реализация существует.

## Основные группы

| Материал | Как использовать |
|---|---|
| Stage 1 | История input/Docker проверок и обслуживания машины |
| Stage 2 | Прежний JS-плеер, visual review, ручные anchors, протокол оценки |
| Stage 3 | Python baseline, JS geometry, начальный C++/CUDA, curve и assumed geometry |
| Stage 4 | Каталог, контракт matching JSON, прежние ROS2/p95 измерения |
| Stage 5 | Развитие оси/фильтра, модель, direct/ROS интеграции и отдельные эксперименты |
| reports | Датированные bug/readiness/methodology срезы; не текущая инструкция |
| dataset/README | Исходная инструкция поставщика для zst; текущая упаковка — два TAR без расширения |
| artefacts Markdown | Локальные подписи результатов, не распространяются через Git |
| .venv Markdown | Лицензии/справки сторонних пакетов; не проектная документация и не объект редакторской очистки |

Синтетика, CUDA, arc, ICP/движение, hidden-tail и multi-hypothesis относятся к исследованиям проекта, но не к стандартному запуску `tangent + model_v1`. Старый 2D YOLO tutorial удалён из корневого README как нерелевантный этому решению; его исходный текст остаётся в истории Git коммита 4d5bb30.

## Восстановление недоступных артефактов

В четырёх stage_3 run-документах девять targets отсутствуют локально. Ссылки заменены явной пометкой, а не фиктивными файлами. Повторный запуск нынешним кодом создаёт **новый** эксперимент; он не восстанавливает побитно историческое evidence без той же версии кода/config/input. Здесь команды только документированы, не выполнялись.

Предусловия: оба исходных архива; Docker-образ проекта с ROS/NumPy/Matplotlib; Node.js на хосте для старого JS replay; `artefacts/stage_2/player_doubleT_obstacle/manifest.json` с `visualization_overlay.reference_cross_section`. Последний файл нужен старому replay-скрипту, но не текущему direct-плееру. Его получение описывается историческим Stage 2 exporter; без файла этот исторический replay запускать нельзя.

Проверка входов из корня PowerShell:

```powershell
Get-Item -LiteralPath 'dataset/for_hackathon/new_data', 'config/geometry_new_data_experiment.yaml', 'artefacts/stage_2/player_doubleT_obstacle/manifest.json'
node --version
$projectRoot = (Get-Location).Path
$restoreRoot = Join-Path $projectRoot ('artefacts/history_restore_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
New-Item -ItemType Directory -Path $restoreRoot | Out-Null
```

Создать новый экспорт 1050–1150 для недоступных baseline summary/frames, затем visual_replay/overview:

```powershell
docker run --rm -e PYTHONPATH=/workspace/src --mount "type=bind,source=$projectRoot,target=/workspace,readonly" --mount "type=bind,source=$restoreRoot,target=/output" lidar-mosmetro3d:stage-4-cpu-viewer python3 /workspace/scripts/experiment_new_data_baseline.py --archive /workspace/dataset/for_hackathon/new_data --output /output/baseline --start 1050 --count 101 --config /workspace/config/geometry_new_data_experiment.yaml --export-xyz
if ($LASTEXITCODE -ne 0) { throw 'Historical input export failed' }
node scripts/replay_new_data_visual.cjs (Join-Path $restoreRoot 'baseline') (Join-Path $restoreRoot 'baseline')
if ($LASTEXITCODE -ne 0) { throw 'Historical JS replay failed' }
docker run --rm --mount "type=bind,source=$projectRoot,target=/workspace,readonly" --mount "type=bind,source=$restoreRoot,target=/output" lidar-mosmetro3d:stage-4-cpu-viewer python3 /workspace/scripts/render_new_data_transfer.py /output/baseline
```

`stage_3_curve_rail_axis_run` и `stage_3_five_steps_status_run` повторяли тот же экспорт в разных выходных папках. Для новых сравнений:

```powershell
node scripts/replay_new_data_visual.cjs (Join-Path $restoreRoot 'baseline') (Join-Path $restoreRoot 'curve_rail_axis')
node scripts/replay_new_data_visual.cjs (Join-Path $restoreRoot 'baseline') (Join-Path $restoreRoot 'five_steps_status')
```

Для трёх targets `new_data_geometry_review` сначала нужны probe `.npy` для кадров 0/5500/10000. Экспортёр сохраняет `.npy` при `--indices`; затем существующий prepare-скрипт создаёт frames/summary и XYZF:

```powershell
docker run --rm -e PYTHONPATH=/workspace/src --mount "type=bind,source=$projectRoot,target=/workspace,readonly" --mount "type=bind,source=$restoreRoot,target=/output" lidar-mosmetro3d:stage-4-cpu-viewer python3 /workspace/scripts/experiment_new_data_baseline.py --archive /workspace/dataset/for_hackathon/new_data --output /output/probe --indices 0 5500 10000
if ($LASTEXITCODE -ne 0) { throw 'Probe export failed' }
docker run --rm --mount "type=bind,source=$projectRoot,target=/workspace,readonly" --mount "type=bind,source=$restoreRoot,target=/output" lidar-mosmetro3d:stage-4-cpu-viewer python3 /workspace/scripts/prepare_stage_3_geometry_review.py --probe /output/probe --output /output/geometry_review
if ($LASTEXITCODE -ne 0) { throw 'Probe preparation failed' }
node scripts/replay_new_data_visual.cjs (Join-Path $restoreRoot 'geometry_review') (Join-Path $restoreRoot 'geometry_review')
if ($LASTEXITCODE -ne 0) { throw 'Geometry replay failed' }
docker run --rm --mount "type=bind,source=$projectRoot,target=/workspace,readonly" --mount "type=bind,source=$restoreRoot,target=/output" lidar-mosmetro3d:stage-4-cpu-viewer python3 /workspace/scripts/render_new_data_transfer.py /output/geometry_review
```

Аргументы/предусловия сверены с `experiment_new_data_baseline.py`, `replay_new_data_visual.cjs`, `prepare_stage_3_geometry_review.py`, `render_new_data_transfer.py`; полный исторический прогон не повторялся. Новые файлы остаются в новом каталоге, прежние численные результаты документов не заменяются.
