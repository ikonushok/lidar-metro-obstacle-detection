## Задача

- Goal: добавить воспроизводимую development-only вставку параметрических препятствий в реальный `PointCloud2` по фактическим направлениям наблюдаемых лучей и каталог первой синтетической выборки из отдельных сценариев.
- Наблюдаемая проблема или исходный claim: доступен только один независимый положительный проезд; настройка и проверка фильтра на нём создаёт риск подгонки под один сценарий.
- Non-goals: не доказывать real-world recall; не менять детектор, envelope, оси, единицы, TF, пороги, сообщения или исходные bag; не моделировать физически достоверную интенсивность, multi-return и движение лидара.
- Source of truth: `docs/README_methodology.md` §17, `docs/README_dataset_audit.md`, фактическая схема `PointCloud2`, конфигурация синтетического сценария.
- Пункт/раздел ТЗ и обязательный результат: дополнительный инструмент разработки и сценарной проверки; не обязательный runtime-компонент MVP.
- Этап `docs/README_work_plan.md`: этап 5, оценка и адресные исправления.
- Целевое окружение: Ubuntu 22.04 + ROS 2 Humble + Docker; фактическая среда проверки: локальные unit-тесты Python, затем доступный Docker-тест.
- Входные данные и единицы: `PointCloud2`, единицы `m` только в явно помеченном `SYNTHETIC_DEVELOPMENT_ONLY` контракте.
- Конкретный bag/версия/интервал, топик и объём выборки: реализация не привязана к bag; пример предназначен для `/sensing/lidar/hesai128/pointcloud`, `frame_id=lidar_livox`; replay не входит в первую локальную проверку.
- Факты из аудита: поля `x/y/z/intensity/ring/timestamp`, `point_step=26`; много нулевых XYZ; Livox-положительный и прочие записи нельзя неявно смешивать как один сенсорный домен.
- Рабочие frames и направление transforms: только identity `lidar_livox <- lidar_livox`; координаты препятствий заданы непосредственно в source frame. Преобразования не выполняются.
- Режим baseline/расширений: автономный генератор тестовых данных; не выдаёт `CLEAR`, safety decision или результат детекции.
- Временная база: header и per-point timestamps копируются без изменения; latency измеряется `time.perf_counter`; deskew и внутрискановое движение не моделируются.
- Allowed files: новый модуль в `src/`, пример config, узкие тесты, эта спецификация и отдельный run-отчёт.
- Files to avoid: детектор, geometry contract, C++ pipeline, исходные bag, пороги и существующие отчёты.
- Защищённые контракты: schema/offsets/endianness/row padding `PointCloud2`, source frame, units, timestamps, запрет safety/CLEAR claims.
- Deliverables: ray casting по oriented box, arbitrary-axis cylinder и ellipsoid; составные объекты; отдельные сценарии для стоящего/лежащего человека, собаки в двух позах, чемодана, низкой коробки, лома, лопаты, куртки/свёртка, трубы, кабеля и ремонтной тележки; fixed/cycle выбор сценария; сохранение структуры сообщения; JSON ground truth; ROS 2 wrapper; tests; документация запуска; центральный `docs/README_synthetic_obstacles.md` с матрицей выборки, manifest, split, обучением и проверкой.
- Путь отчёта: `docs/stages/stage_5/stage_5_synthetic_obstacle_generation_run.md`.
- Основной агент: текущий агент по `agents/lidar_obstacle_pipeline.md`.
- Нужен ли `safety_geometry_reviewer`: да, отдельный проход текущего агента, потому что код создаёт геометрию в source frame; независимость review не заявляется.
- Нужен ли validation reviewer: отдельный проход после safety-review для проверки evidence и ограничений claim.
- Validation target: L2 для кода генератора (статическая/межфайловая проверка и unit-тесты); не уровень работоспособности детектора на реальном bag.
- Validation method: unit-тесты пересечений, окклюзии, frame mismatch, сохранения полей/endian/padding и детерминированного dropout; Docker unit-test при доступности.
- Acceptance criteria: препятствие заменяет только лучи с более близким пересечением; фон за объектом окклюдируется; точки перед объектом и невалидные записи неизменны; составной объект имеет единый object-level ground truth и наблюдаемые part-level счётчики; каждый запрошенный сценарий присутствует и выбирается детерминированно; сообщение сохраняет schema/header; ошибки контракта не публикуют ложное дополненное облако.
- Stop conditions: необходимость менять защищённую геометрию/формат, добавлять тяжёлую зависимость или объявлять качество на synthetic данных.
