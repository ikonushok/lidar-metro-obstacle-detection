## Цель и согласованный объём

Проверить, можно ли расширить наблюдаемую рельсовую ось ближе 4 м и в сторону 56 м на `doubleT_obstacle` и `new_data`, не выдавая экстраполированную геометрию за наблюдаемую.

Согласовано:

- параметризовать ближнюю границу поиска рельсов и испытать начало оси около 3 м;
- отдельно испытать поиск наблюдаемых рельсов в дальнем диапазоне 60–80 м;
- предусмотреть внешний источник траектории как отдельный режим при наличии валидного входа.

Отложено до прогона обоих наборов и идентификации помех внутри габарита:

- решение об использовании экстраполяции оси;
- включение экстраполированных участков в runtime и в решение `CLEAR`/`OBSTACLE`.

## Non-goals

- Не добавлять синтетические рельсовые пары и не продолжать ось через ненаблюдаемый участок.
- Не менять профиль поезда, safety margin, frame, единицы, временную базу и правила принадлежности габариту.
- Не считать точки внутри габарита подтверждёнными объектами без проверки события/кадров.
- Не заявлять восстановление до 56 м до фактического replay evidence.

## Входы и режим

- `dataset/for_hackathon/doubleT_obstacle` — положительный исследовательский проезд с контрольными кандидатами.
- `dataset/for_hackathon/new_data` — второй проезд без подтверждённой объектной разметки.
- Рабочий frame совпадает с frame входного облака; преобразование координат не выполняется.
- Геометрия оценивается покадрово только по наблюдаемым точкам текущего облака.

## Карта обработки

`PointCloud2 -> quality gate -> station-local rail candidates -> observed rail-pair selection -> supported curve axis -> train envelope membership -> diagnostics/result JSON`

## Contracts at risk

- Параметр ближней границы меняет область поиска рельсов и требует негативной проверки ложных пар.
- Неподдержанный участок обязан оставаться `UNKNOWN`; `UNKNOWN` не равен `CLEAR`.
- Результат обязан явно сообщать фактическую конфигурацию поиска.
- Точки внутри envelope не удаляются и не подавляются новым поиском оси.

## Acceptance

1. Ближняя граница задаётся ROS/runtime-параметром, отражается в результате и не меняет остальные геометрические контракты.
2. Есть узкий тест конфигурации и replay на обоих наборах с одной и той же парой конфигураций.
3. Для каждого прогона сохранены диапазон поддержанной оси, `core/margin/outside/unknown` и случаи помех внутри габарита.
4. Дальний эксперимент отличает наблюдаемую поддержку от гипотезы; без наблюдаемой пары участок остаётся `UNKNOWN`.
5. Выполнены отдельные safety- и validation-проходы; итоговые утверждения ограничены фактическими данными.

## Состояние выполнения

Реализация и два полных прогона завершены 2026-09-22. Экстраполяция и внешний источник траектории в runtime не добавлялись.

## Реализация

- В `curve_envelope_node` добавлены ROS-параметры `rail_forward_min_m`, `rail_forward_max_m`, `rail_station_length_m`, `rail_cell_width_m`; их фактические значения возвращаются в каждом результате, включая `UNKNOWN`.
- Значение по умолчанию сохранено: `rail_forward_min_m=3.0`. Эксперимент `2.0` включается явно через launcher.
- Runtime, HTTP manifest и PowerShell launcher передают и проверяют конфигурацию; имя контейнера включает ближнюю границу.
- Исправлена смена входного frame в плеере: при переходе `hesai_lidar <-> lidar_livox` завершается вся группа старого процесса ROS2.
- Для полного офлайн-аудита добавлен потоковый C++ runner тех же `DetectAutoRails` и `AnalyzeCurveEnvelope`. На 20 одинаковых кадрах его геометрический результат совпал с ROS2 `20/20`.
- Никаких синтетических пар, продолжения оси или преобразований координат не добавлено.

## Результаты полных прогонов

| Набор | `forward_min` | Кадры | Поддержанная ось | `UNKNOWN` | Кадры до 56 м | Core returns |
|---|---:|---:|---:|---:|---:|---:|
| `doubleT_obstacle` | 3 м | 201 | 201, начало 4 м, максимум 44 м | 0 | 0 | 191 414 |
| `doubleT_obstacle` | 2 м | 201 | 201, начало 3 м, максимум 43 м | 0 | 0 | 218 252 |
| `new_data` | 3 м | 11 271 | 11 136, начало 4 м, максимум 46 м | 135 | 0 | 7 459 501 |
| `new_data` | 2 м | 11 271 | 11 117, начало 3 м, максимум 45 м | 154 | 0 | 9 859 811 |

Вывод по ближней зоне: `forward_min=2` действительно даёт первую станцию оси на 3 м, но на `new_data` уменьшает число поддержанных кадров на 19, добавляет 19 `UNKNOWN`, сокращает лучший дальний конец на 1 м и увеличивает число core returns на 2 400 310. Эти returns не являются подтверждёнными помехами: в них входит штатная инфраструктура. Поэтому параметр доступен для просмотра, но новый default не принят.

Вывод по дальности: ни в одном из 11 472 кадров двух наборов наблюдаемая непрерывная пара рельсов не поддержала ось до 56 м. Простая смена ближней границы дальность не восстанавливает.

## Контрольные помехи

- `OBS-002`, кадр 55, около 56.37 м: точка не попала в core/margin; поддержанная ось кадра заканчивается около 39 м, поэтому точка остаётся вне доказанной области, то есть не может считаться проверенной помехой внутри габарита.
- `OBS-003`, кадр 160, около 3.89 м: при начале оси 3 м точка также не попала в core/margin. C++-выход хранит core/margin indices, поэтому для этой отрицательной принадлежности не заявляется более узкий класс без отдельного evaluator-а.
- В `new_data` независимой объектной разметки нет. Массовые core returns — кандидаты, а не идентифицированные помехи.

Следовательно, условие для решения по пункту 4 пока не выполнено: оба набора прогнаны, но подтверждённых помех внутри габарита нет. Экстраполяция остаётся отложенной.

## Внешняя траектория

## Safety review

Verdict: `PASS_WITH_RISKS` для экспериментального режима.

- `UNKNOWN` нигде не превращается в `CLEAR`; `safety_decision_permitted=false` сохранён.
- Default, профиль поезда, margins, frame/units/time и envelope membership не изменены.
- На дату этого отчёта экстраполяции и скрытого доверия к ненаблюдаемой геометрии не было. Текущий runtime позднее получил явную synthetic continuation с diagnostics; см. [stage_5_curve_limited_horizon.md](stage_5_curve_limited_horizon.md). Она остаётся `ASSUMED` candidate-only и не разрешает `CLEAR`.
- Остаточный риск: ближняя зона заметно увеличивает штатные core returns и немного ухудшает поддержку оси. До ручной идентификации/разметки её нельзя принимать как рабочий default.

## Validation review

Verdict: `PASS_WITH_RISKS`.

- `L4` достигнут только для узкого утверждения о диапазоне наблюдаемой оси: два полных существенно разных набора, одинаковые конфигурации и непрерывное покрытие кадров.
- Для качества обнаружения помех уровень не выше `L1`: две пользовательские контрольные точки не являются независимой ground truth и не подтверждены внутри габарита; `new_data` не размечен.
- Нельзя заявлять recall/precision, восстановление оси до 56 м или готовность к safety-решению.
