Цель: просмотр new_data и переключение записей без смешения кадров/разметок. Этап 2, patch. Основной агент текущий; отдельные safety и validation проходы. Контракты геометрии/XYZ/времени не менять. Накопление, новые пороги и детекция по неподтверждённым осям вне scope.

Источник: dataset/for_hackathon/new_data — tar без сжатия, 90 121 656 320 байт. Metadata: sqlite3, /lidar_points PointCloud2/cdr, 11 271 сообщений, 1 199.883468908 с, 221 части. Свойства metadata не доказывают проверку всех облаков.

Allowed: отдельный HTTP каталог/ленивое чтение архива и launcher, raw player selector, tests и этот отчёт. Raw/archive, существующие manifests и geometry configs не перезаписывать. Временная распаковка одной части около 408 МБ, автоматически заменяемый служебный cache. Только allowlisted HTTP маршруты, bind localhost. Исходный frame сохраняется, transform отсутствует. Новая запись без доверенного профиля: raw + UNKNOWN.

Acceptance L1: реальное декодирование начала/середины/конца, raw encoding без прореживания; смена записи полным переходом с предупреждением о несохранённых отметках; отдельные URL/identity; корректные ошибки. ROS2 Humble Docker, существующий образ + текущие исходники read-only; без установки зависимостей. Полный decode всех кадров/метрики помех не заявляются.

## Реализация

- scripts/serve_stage_2_catalog.py: каталог готовых player manifests и new_data; чтение произвольного кадра tar/SQLite/CDR по запросу; один временный файл части и до трёх XYZ кадров в памяти. Имя временного файла фиксируется сервером, пути TAR не используются для распаковки каталогов. SQL read-only, проверка фактического count для каждой читаемой части; ошибку нельзя выдать за пустое облако. API не выдаёт произвольные файлы репозитория.
- scripts/run_stage_2_catalog.ps1 и маршрутизация из run_stage_2_player.ps1: используют имеющийся образ и текущие исходники через readonly mount. Host publish только 127.0.0.1. Прежний сервер именно этого проекта остановлен и заменён каталогом; исходные данные не удалены. Остановка нового: `docker stop lidar-player-catalog-8080`.
- HTML: выбор записи, загрузка полного нового документа (отдельные cache/geometry/records), предупреждение beforeunload при отметках, метаданные и XYZ ленивых кадров с проверкой request token. Новая запись — общий вид, автоматическая геометрия disabled/UNKNOWN. Номинальное воспроизведение 10 Гц плюс I/O явно подписано; точный bag offset выводится после чтения. Это не синхронный real-time replay.
- README_dataset_audit дополнен отдельной новой выборкой, без распространения прежних выводов на неё.

## Safety-review (текущий агент, отдельный проход)

PASS_WITH_RISKS для просмотра. Нет межкадрового накопления и переноса габарита lidar_livox на hesai_lidar. Все конечные ненулевые XYZ сохраняются, архив не изменяется; геометрия не подгоняется. Разметка может быть потеряна при подтверждённом уходе со страницы: браузер предупреждает, экспорт JSON доступен. Само предупреждение в browser smoke не проверялось. Нельзя считать новое облако поверенным относительно поезда. Отдельного независимого reviewer не было.

## Полная проверка движения — спецификация

Пользователь запросил проверку всех 20 минут. Новый `analyze_new_data_motion.py` декодирует все 11271 облако последовательных SQLite частей из архива и сохраняет компактные покадровые метрики. Для каждого соседнего кадра: overlap voxel 0.2 м и nearest-neighbour по возвращениям 4–35 м; каждые 50 кадров (примерно 5 с) — trimmed rigid ICP. Это независимые от предположений об осях LiDAR признаки изменения неподвижного тоннеля в системе датчика. Вывод не является одометрией, не определяет состояние поезда, не годится для deskew/накопления/габарита. До старта проверяются topology/тип/serialization/topic/source_frame/count каждой части; архив остаётся read-only.
