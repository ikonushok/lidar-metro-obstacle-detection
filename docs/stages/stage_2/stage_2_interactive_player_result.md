## Цель и результат

Добавлен локальный браузерный плеер `doubleT_obstacle`. Он подготавливает отдельный бинарный файл `.xyzf` для каждого кадра и показывает в браузере только текущий кадр: запуск/пауза, шаг назад/вперёд, слайдер, скорость 0,25–4× и ракурсы «вперёд», «сверху», «сбоку», «свободное вращение».

В базовом режиме подготовщик и плеер показывают **все finite, non-zero XYZ returns в исходном порядке**, без sampling, ROI, voxelisation или межкадрового накопления. `(0,0,0)` и non-finite записи не являются пространственными возвратами: их число сохранено в manifest и видно в UI. Плеер держит небольшой cache полных файлов только для скорости навигации; cache не изменяет ни один кадр. Если WebGL/GPU не может разместить полный кадр, UI должен показать ошибку, а не проредить облако.

Добавлен выключенный по умолчанию флаг «Только справочный габарит по X/Z» и четыре независимых поля: «Слева по ходу (X−)», «Справа по ходу (X+)», «Сверху», «Снизу» (0–10 м, шаг 0,1 м; начальное значение каждого — 0,5 м). В свободном ракурсе экранные стороны меняются при вращении камеры, поэтому left/right определены относительно движения по гипотезе `−Y`, а не относительно края экрана. Флаг скрывает точки только вне поперечно-вертикальной reference band: при четырёх значениях 0,5 м это X `[-1,9; 1,9]` и Z `[-0,5; 4,2]`. Оранжевая рамка показывает её сечение на 10 м, а UI выводит точные X/Z границы. **По продольной оси −Y фильтра нет**, поэтому точки впереди не отбрасываются. `Сверху = 0` означает отсутствие добавочного запаса над reference-верхом Z=3,7, но не удаляет точки, находящиеся ниже него. Флаг не изменяет локальные `.xyzf`, не влияет на detector и не является safety margin или утверждённым габаритом.

Добавлен отдельный выключенный по умолчанию режим «Экспериментальные кластеры». Он берёт точки внутри текущей X/Z-band даже если отображение raw-облака не обрезано, объединяет заполненные voxel-ячейки в 26-связные компоненты и подсвечивает компоненты, имеющие не меньше выбранного числа точек. Начальные ручные значения — ячейка 0,25 м и 15 точек; оба параметра видимы и не являются калиброванными порогами. Цветные компоненты — кандидаты для ручного просмотра, а не классификация объекта, не подтверждённое препятствие и не safety-вывод.

Красный wireframe 2,8 × 3,7 м рисуется лишь по `visualization_overlay` из `config/geometry_contract.yaml`; в интерфейсе постоянно указано `UNCONFIRMED / manual review only`. Направление `forward=-Y`, `lateral=X`, `vertical=Z`, метры, ноль оси пути и уровня рельса — рабочая визуальная гипотеза. Это не extrinsics, не валидный `T_target <- source`, не габарит в `lidar_livox` и не safety envelope. Поэтому вывод геометрии и любой вывод о препятствии остаются `UNKNOWN`.

## Запуск

Из корня репозитория:

```powershell
./scripts/run_stage_2_player.ps1
```

Скрипт ждёт доступности локального server и сам открывает `http://localhost:8080` в браузере по умолчанию. Первый запуск создаёт Docker image и полный локальный export в `artefacts/stage_2/player`; повторный запуск использует уже подготовленные кадры. Чтобы создать их снова после изменения входа либо YAML:

```powershell
./scripts/run_stage_2_player.ps1 -RebuildData
```

`Ctrl+C` останавливает локальный web server. Если автоматическое открытие не нужно, передайте `-NoBrowser`. Для одной только подготовки без сервера предназначен `./scripts/validate_stage_2.ps1`.

В статусе кадра видны номер, относительное время bag, raw header timestamp, количество отображённых и исходных записей, число `(0,0,0)` и минимальная евклидова норма валидного raw-return. Последняя величина подписана как значение только в гипотезе метров и **не является расстоянием до препятствия**. Bag/header clocks не сравниваются.

## Ручная проверка осей и reference overlay

1. В ракурсе «Строго вперёд (−Y)» убедиться только в визуальной правдоподобности протяжения тоннеля; это не подтверждает направление движения.
2. Сравнить «Сверху» и «Сбоку» с внешней калибровкой/схемой лидара, когда она будет получена. До этого X/Y/Z не менять.
3. Включить свободное вращение и проверить, что красный контур остаётся лишь удобной справочной рамкой, а не доказательством положения рельсов или вагона.
4. Не фиксировать объект как obstacle и не определять его дальность по этому экрану без отдельной разметки, extrinsics и источника габарита.

## Непроверенное, риск и следующий тест

Не подтверждены оси, метрические единицы, extrinsics, положение датчика/рельсов, габарит, margin, event labels и связь часов. Визуальный отступ 0–10 м — пользовательский параметр отображения, не калибровочное значение. Полный export создаёт значительный локальный объём (порядка сотен MB–~1 GB, зависит от числа valid returns); размер и WebGL memory должны быть измерены при первом запуске, а не предполагаются здесь.

Следующий минимальный тест: выполнить `./scripts/validate_stage_2.ps1`, убедиться в `prepared_frames: 201` и `decimation: NONE`, затем выполнить `./scripts/run_stage_2_player.ps1`, открыть первый, средний и последний кадры, проверить все четыре ракурса и зафиксировать результат/версию браузера в этом отчёте. Это подтвердит только работоспособность visual tool на одном реальном bag, не геометрию и не безопасность.
