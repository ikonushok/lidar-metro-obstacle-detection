## Задача — 2026-09-20

- Режим: patch, недостающая функция Stage 2. Пользователь просит исправить ручной-only режим после демонстрации нового плеера.
- Цель: покадровая автоматическая гипотеза двух рельсов, зелёная midpoint-ось, единая геометрия сетки/reference-габарита. Не собирать тоннель из накопленных кадров.
- Источники: запрос, docs/README_methodology.md §5–6, docs/README_dataset_audit.md, действующий reference profile manifest. Визуализация для MVP; требований обнаружения/дальности ТЗ этой задачей не доказываем.
- Вход: существующий export doubleT_obstacle, сначала кадры 0/100/200 как development, не held-out. XYZ единицы m_ASSUMED, source frame без преобразования; Z вверх и поиск вдоль -Y — явно обозначенные допущения manifest. Bag time только проигрывание, header только идентификация.
- Non-goals: ROS2, калибровка, изменение размеров профиля/отступов, detector Stage 3, карта, tracking, deskew, CLEAR/NO_OBSTACLE.
- Allowed: web/stage_2_raw_player.html, web/stage_2_review_layers.js, новый модуль и конфигурация поиска рельсов в web/, scripts/run_stage_2_player.ps1, tests для автоматической геометрии/интеграции, этот отчёт и served copies/диагностические артефакты.
- Защищены: исходные XYZ/manifest/bags, config/geometry_contract.yaml и пороги detector. Параметры нового visual-only поиска должны быть явными, не считаться калибровкой.
- Поток: raw XYZ -> отдельный поиск поддержки рельсов -> геометрическая гипотеза/UNKNOWN -> overlay в source XYZ. Исходные точки не удаляются и не переносятся.
- Acceptance: две независимо поддержанные продольные линии; контроль ширины/остатков/покрытия; ограничение поддержанным участком; неоднозначность/отсутствие рельсов даёт UNKNOWN без фиктивного fallback. Сетка и габарит используют ровно ту же ось; manual override сохраняется только в текущем кадре; raw-only работает.
- Проверки: synthetic offset/yaw/grade, отсутствие/один рельс, шум/кривая/плоскость, совпадение сечений, неизменность XYZ, переходы кадров; smoke на development export и в браузере. Node tests + PowerShell parser. Новые зависимости не нужны.
- Основная роль lidar_obstacle_pipeline. Safety-review затем validation — отдельные проходы текущего агента, не независимый review. Target L1 + браузерная проверка одного export. Целевая среда проекта Ubuntu 22.04/Humble/Docker; текущая проверка Windows/Node + действующий Docker HTTP.
- Stop: нет достаточной поддержки рельсов — диагностировать, не подменять их осью тоннеля; не объявлять найденную пару физически подтверждённой или пригодной для решения о безопасности.

## Результат

Реализован web/stage_2_auto_rails.js с отдельным stage_2_auto_rails_config.json.
Поиск не использует старую floor-path polyline и не накапливает оценку из слоёв.
В каждом продольном сечении нижняя поверхность оценивается с равным весом
поперечных ячеек (плотные стены не должны определять уровень пола). Кандидат
головки должен возвышаться над обоими соседними участками; затем ищутся пары
с допустимой шириной/перепадом высот. Глобальный детерминированный consensus
двух линий проверяет прямизну, параллельность, покрытие, разрывы, остатки,
неоднозначность и ширину/перепад на обоих концах. При избыточном числе пар
срабатывает лимит вычислительного поиска с UNKNOWN, а не выбор первой пары.

Середины двух рельсов задают одну ось для сетки, reference-профиля и
визуального crop. Оранжевые опорные маркеры — реальные source-точки;
положение оси и рельсовых линий — результат fit. Продольные границы берутся
по центрам крайних поддержанных 2-метровых сечений. Короткие пробелы до
maxGap разрешены моделью; это не сплошная измеренная поверхность рельсов.
Зелёная линия показана поверх облака/сетки, чтобы не исчезать из-за depth test.
Сетка отсчитывает длину от начала поддержанного участка, не от датчика.

В плеере по умолчанию включены автоось, сетка и габарит. UNKNOWN виден даже
при закрытой панели. Режимы «Ручные 4 точки» и «Без разметки» сохранены;
manual не получает автоматически оценку другого режима/кадра. Crop сбрасывается
при переходе на другой кадр. Отсутствие конфигурации/неподдержанные допущения
осей дают полное исходное облако и UNKNOWN без фиктивного габарита.
Сохранённые результаты Stage 3 остаются отдельным явно обозначенным слоем
со старой геометрией. Размеры reference-профиля и отступов не изменены.

Launcher копирует HTML, два JS и JSON поиска при каждом запуске, открывает
`http://localhost:8080/?v=auto-rails-1`. Новая версия явно названа
«Рельсы и габарит · автоматическая ось». Исходные bags/xyzf/manifest и
config/geometry_contract.yaml не изменялись; сборка Docker не потребовалась.

## Safety-review — отдельный проход текущего агента

PASS_WITH_RISKS для visual-only функции: исходные позиции не преобразуются,
не накапливаются и не подавляются; нет fallback к X=0; UNKNOWN не становится
CLEAR; old Stage 3 явно отделён; margin/profile/ROS2 не изменены. Проверено,
что fit проверяет ширину/перепад на обоих концах, а не только в начале;
после уточнения этой проверки повторены unit/integration и 201-frame regression.
Проверка не независимая. Порогам не присвоен статус калиброванных.

Риски: регулярные возвышенные конструкции могут имитировать рельсы; ролл
и кривизна пути не моделируются; источник Z/метрических единиц не подтверждён.
Геометрия вне поддержанного интервала неизвестна, включая ближние 0–4/6 м.
Внутри интервала допустимы короткие пробелы наблюдений. Оранжевые опоры и
RMS позволяют проверять гипотезу, но не устраняют необходимость rail ground truth.

## Validation — последующий проход тем же агентом

L1 + browser integration и полный computational replay одного development
export. Не L4, не независимый held-out test, не валидация safety detector.
Реализованы автоматическая visual-гипотеза, единая ось overlay и диагностика.
Не заявляются калибровка, полный тоннель/карта, deskew, tracking, TTC,
пересчёт опасности Stage 3 или пригодность для управления поездом.

Следующий минимальный тест: независимо разметить головки рельсов в нескольких
сечениях этих кадров и сравнить поперечную/вертикальную ошибку, отдельно по
дальности; затем проверить другой проезд, кривые/стрелки и перекрытия. Только
после этого отдельно согласовать использование оси в расчёте опасной зоны.
