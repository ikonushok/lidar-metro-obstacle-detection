2026-09-20. Пользователь одобрил порядок: точки/измерения → ось рельсов →
габарит/отступы → отдельные результаты/фильтры. Режим patch, Stage 2 visual
review. Основная роль lidar_obstacle_pipeline; затем safety и validation
отдельными проходами текущего агента. Target L1 + browser smoke.

Вход: неизменённые xyzf и manifest doubleT_obstacle. Рабочий frame — source
frame (identity). Метры остаются допущением manifest, bag time только для
проигрывания, header для идентификации. ТЗ: средство просмотра для MVP в
среде Ubuntu 22.04/Humble/Docker; новый safety detector не заявляется.

Ручной путь: 4 source-точки, по паре на головках рельсов в двух сечениях
одного кадра. Середины пар задают отрезок оси. Длина/смещение/yaw/уклон
берутся из этих точек, профиль сохраняет размеры manifest. Вертикаль source Z;
поперечный уклон не моделируется. Геометрия только между выбранными сечениями,
без экстраполяции. Две станции не доказывают прямизну промежуточного пути.
На кривой такая ручная модель не применима.

Все overlay выключены по умолчанию. Ручная ось и отметки привязаны к индексу,
header timestamp и source frame; между кадрами не переносятся. При отсутствии
ручной геометрии габарит и crop недоступны. Crop только визуальный, сохраняет
точки вне размеченного продольного интервала (unknown), не меняет буфер.
Сохранённые Stage 3/audit показываются отдельными переключателями с подписью
об исходной геометрии; не пересчитывают результат по новой ручной оси.

Allowed: web/stage_2_raw_player.html, новый web/stage_2_review_layers.js,
scripts/run_stage_2_player.ps1 (копирование JS), tests/test_review_layers.cjs,

Проверка: произвольный сдвиг/yaw/уклон, центр сечений совпадает с осью,

## Safety и validation

Отдельный safety-проход текущего агента: PASS_WITH_RISKS для visual-only
инструментов. Габарит и crop используют одну параметризацию, трансформации
исходных точек отсутствуют. Нет CLEAR, подавления в detector, изменения
margin YAML или переноса ручной геометрии на другой кадр. Сохранённые
результаты детектора явно обозначены как результат прежней геометрии.
Риск: точность ручных clicks, ошибочная идентификация головок рельсов,
source Z как вертикаль и предположение прямого участка; эти условия UI
не подтверждает автоматически. При наложении нескольких source-точек
на один экранный пиксель пользователь должен проверить выбор с другого вида.

Последующий validation-проход тем же агентом: L1 + browser integration
для перечисленных функций на одном export. Не независимый review и не
проверка физической оси, качества детектора или функциональной безопасности.
Не проверены другие bags, полный длительный replay, восстановление JSON
после перезагрузки (импорт не реализован), производительность на стенде.
Следующий минимальный тест: пользователь выбирает реальные две пары рельсов
в удобном ракурсе, проверяет midpoint-ось на всём отрезке и экспортирует
anchors. Автоматическая ось и пересчёт detector по ней остаются отдельной
задачей после проверки входной геометрии.
