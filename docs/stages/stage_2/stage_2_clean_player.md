2026-09-20. Режим patch, по прямому запросу пользователя пересобрать просмотр
заново вместо дальнейшей правки старых слоёв.

Цель: один кадр PointCloud2 → существующий полный XYZ export → один объект
Points с identity transform. Смена кадра заменяет геометрию. Никакого crop,
подгонки к прямой, объединения кадров, сетки, габарита или candidate layers.
Это основание для последующей проверки рельсов, а не модель опасной зоны.

Этап 2, visualization/manual review. Source of truth: бинарные xyzf и manifest
doubleT_obstacle (201 кадров), src/stage_2_player.py и exporter. Единицы и
extrinsics остаются предположениями. T_source<-source = identity; время
проигрывания — разницы bag_offset_seconds, header timestamp только отображается.
Требование среды Ubuntu 22.04/Humble/Docker сохраняется, новый UI использует
уже экспортированные файлы и установленные Three.js assets.

Allowed: web/stage_2_raw_player.html, scripts/run_stage_2_player.ps1,
tests/test_raw_player.cjs, этот отчёт и копия HTML в served artefacts.
Старый player сохраняется для явного -LegacyLayers. Детектор, конфигурация,
сырые облака и старые отчёты не перезаписываются.

Основная роль — lidar_obstacle_pipeline. Safety и затем validation — отдельные
проходы текущего агента. Target L1 + browser smoke: байтовая идентичность
буфера XYZ, ровно один объект облака после смены кадров, корректный сброс
камеры, первый/средний/последний кадр, диагностика повреждённого входа.
Stop: не заявлять rail calibration, реконструкцию или safety result.

## Результат

Новый web/stage_2_raw_player.html реализован с нуля. Старый web/stage_2_player.html
сохранён; launcher включает его только при -LegacyLayers. Обычный запуск
перекопирует свежий HTML, использует существующие XYZ и не запускает Docker
build или candidate audit. Build нужен при подготовке данных либо отсутствии
образа для нового сервера. Текущий сервер на 8080 переиспользован.

Команды и evidence:

- node --test tests/test_raw_player.cjs: 3/3 PASS. Реальный Three.js; identity
  matrix, удаление старой геометрии, ровно один Points, повреждённый буфер;
  побайтовое совпадение входа GPU с xyzf кадров 0/100/200 — соответственно
  346808/346796/346758 точек. Синтаксис страницы проверен тем же тестом.
- PowerShell Parser.ParseFile scripts/run_stage_2_player.ps1: ошибок нет.
- .\scripts\run_stage_2_player.ps1 -NoBrowser: HTML обновлён, существующий
  сервер на localhost:8080 переиспользован, пересборка и аудит не запускались.
- Браузер Codex: показаны кадры 0, 100, 200, счётчики совпали с manifest;
  осмотрены скриншоты кадра 0 вдоль -Y и кадра 100 сверху. Смена ракурса
  сверху обратно вдоль -Y выполнена. Ошибки загрузки не показаны.

Safety-проход текущего агента: PASS в пределах чистого просмотра. Нет
фильтрации, transforms, полилиний, envelope или выдачи CLEAR. Поле XYZ
сохраняется; опасная зона явно не определена. Код детектора и исходные
файлы данных не менялись. Старый режим сохранён отдельно, его физическая
геометрия данным изменением не проверяется.

Отдельный validation-проход тем же агентом: L1, плюс browser smoke одного
существующего export. Это не независимый review. Заявляется корректность
отображения экспортированных XYZ, не сборка тоннеля из совмещённых кадров.
Полный bag заново не декодировался и 201 кадров подряд не просмотрены.
Автопроигрывание всех кадров, другие bags и новый Docker build не проверены.
Предыдущие тесты на названия функций не доказывали совпадение оси с рельсами;
для этого результата использована проверка реальной геометрии Three.js.

Следующий минимальный этап: согласовать вид полного исходного облака,
после чего отдельно получить ось рельсов по точкам. Предположение X=0
нельзя снова использовать как доказательство положения рельсов.
