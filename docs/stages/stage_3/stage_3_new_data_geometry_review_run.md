Дата: 2026-09-20. Этап 3, шаг 1 обновлённого плана — геометрия. Спецификация задачи: [план проверки](stage_3_new_data_geometry_review_plan.md). Цель — ограниченно проверить предположения исходного offline-переноса на сохранённых коротких evidence и подготовить следующее изменение для поворотов. Это не калибровка, не оценка качества детекции и не проверка real-time.

## Вывод

Повороты блокирует не только отсутствие «длинной» оси: текущий AutoRails выдаёт единственный прямой сегмент в frame лидара, даже когда его центр заметно уходит по X. Он не представляет кривую, не хранит явные пары опоры как полилинию и не отличает поворот от стрелки, окклюзии или инфраструктуры. Поэтому прямой габарит нельзя продлевать за подтверждённый сегмент: на кривой он захватывает штатные возвраты либо становится `UNKNOWN`.

На сохранённых кадрах текущая ось дала два локальных сегмента и один отказ. На кадре 5500 центр пары сместился на 0,585 м по X за 22 м по -Y; это уже существенно для габарита, хотя линейный fit внутри этого короткого фрагмента ещё проходит. На кадре 10000 есть 15 станций с парными пиками, но `NO_STRAIGHT_CONSISTENT_PAIR`: одних локальных пиков недостаточно для единой прямой. Причину отказа по этим данным нельзя уверенно назвать поворотом — возможны также сложная инфраструктура, стрелка или пропадание наблюдаемой опоры.

Следующее изменение должно строить **покадровую кривую ось только по непрерывно поддержанным парам рельсов** и sweep того же reference-профиля вдоль неё. До этого, при потере опоры или вне крайних подтверждённых сечений, остаётся `UNKNOWN`.

## Конкретные недостатки текущей модели

1. AutoRails хранит четыре конца одного прямого сегмента. Его `support` — плоский список точек без явной структуры пар для дальнейшей полилинии.
2. Straight fit может быть хорошим на локальных 20–30 м и одновременно быть неверной моделью всего видимого поворота. RMS fit описывает только выбранную прямую, не кривизну пути или ошибку габарита.
3. Отказ `NO_STRAIGHT_CONSISTENT_PAIR` не даёт различить поворот, стрелку, недостаток возвратов и инфраструктуру; корректный безопасный результат уже `UNKNOWN`, но диагностики для планирования не хватает.
4. Нет подтверждённого `base_link <- hesai_lidar`, профиля поезда, запаса и выноса кузова. Поэтому даже корректная полилиния будет только экспериментальной геометрией.
5. Рельсы и низкие препятствия не размечены внутри поддержанных сегментов. Нельзя утверждать, что изменение уменьшает FP/FN или сохраняет recall.

## Спецификация следующего изменения: `CurveRailAxis`

Граница изменения: только покадровая геометрическая гипотеза для existing live-envelope/replay. Ни `geometry_new_data_experiment.yaml`, ни размеры профиля/отступов, ни пороги AutoRails/кластеризации, ни ROS2-интерфейсы не меняются. Карта, tracking, deskew и накопление не включаются.

1. Сделать результат AutoRails явным: добавить backward-compatible `rail_pairs`, где каждая выбранная станция содержит `{source_s_m, left_xyz, right_xyz}`. Выбор станций и все действующие пороги остаются неизменными; новое поле устраняет зависимость от позиции в плоском `support`.
2. Для единственного уже непрерывного run построить `center_i=(left_i+right_i)/2`, упорядоченный по `source_s_m`. Соединить соседние центры ломаной без сглаживания и без экстраполяции. Касательная сегмента — разность центров в XY; поперечная нормаль сохраняет сторону `left/right` и не должна переворачиваться между сегментами.
3. Построить union локальных призм: одно неизменённое сечение reference-профиля на каждом сегменте, высота интерполируется по центрам. Точка — `CORE`/`MARGIN`, если входит хотя бы в один поддержанный сегмент. До первой пары, после последней пары, в разрыве опоры, при невалидной касательной или неоднозначных парах — только `UNKNOWN`; `OUTSIDE` не становится `CLEAR`.
4. Добавить diagnostics: `curve_axis_status`, число пар/сегментов, arclength, границы каждого поддержанного run, причина разрыва и `STRAIGHT_FALLBACK_USED=false/true`. Кадр 1054 обязан выдавать `MISSING_CURVE_AXIS` и `UNKNOWN` для всех возвратов.
5. Сохранять source XYZ, `header_timestamp_ns` строкой и `hesai_lidar <- hesai_lidar`; не использовать ICP как одометрию и не смешивать часы. Deskew остаётся выключенным.

### План проверки изменения

| Сценарий | Проверка | Ожидаемый результат |
|---|---|---|
| Прямой участок | Коллинеарные синтетические пары и saved frame 0. | Полилиния даёт тот же membership, что current straight axis, в пределах существующей численной tolerance. |
| Поворот | Синтетическая дуга и saved frames 5500/1050/1100/1150. | Габарит следует поддержанным центрам, не пересекает пространство, которое принадлежит только прямому продолжению; нет extrapolation за крайний сегмент. Это геометрический тест, не метрика детекции. |
| Низкое препятствие | Низкий singleton/граница внутри swept core. | Немедленный кандидат сохраняется независимо от группировки; фильтра пола/рельсов нет. |
| Потеря опоры | Frame 1054 и искусственный разрыв между парами. | Все точки неподдержанного отрезка `UNKNOWN`, нет расстояния, `CLEAR` и скрытого straight fallback. |

После этого нужен отдельный короткий development replay с теми же сохранёнными кадрами и разметка рельсов/инфраструктуры/низкой помехи внутри поддержанного участка. Только затем можно измерять FP/FN и решать, нужна ли калибровка профиля или deskew.

Подготовщик скопировал в отдельный каталог только три уже сохранённых NPY, проверил finite/non-zero float32 XYZ и записал SHA256 каждого `.xyzf`. AutoRails/live-envelope выполнились на 3/3 экспортов: 2 `AUTO_HYPOTHESIS`, 1 `UNKNOWN`; `source_mutations: 0`, системный статус каждого кадра — `UNKNOWN`. Локальный bundled Python не содержит matplotlib, поэтому PNG отрендерен существующим локальным Docker-образом без установки зависимостей. Архив, bag, конфигурации, пороги, baseline и плеер не запускались и не менялись.

## Валидация и риск

Достигнут L1 только для повторного read-only анализа трёх сохранённых экспортов и существующего 101-кадрового evidence. Это не подтверждает калибровку, оси, метры, детекцию препятствий, безопасный габарит, ROS2 end-to-end или real-time. Проверка safety geometry reviewer не запускалась: рабочий контракт, пороги и decision state не менялись; предложенная `CurveRailAxis` пока не реализована.

Остаточный риск: view в source frame может искажаться движением внутри скана; без extrinsics нельзя перенести рельсовую ось в габарит поезда. В candidate попадает инфраструктура, а отсутствие разметки низкого препятствия не позволяет оценить пропуски. Следующий минимальный тест — реализовать только `rail_pairs` и pure curve membership по этой спецификации, затем выполнить четыре сценария из таблицы на неизменённых сохранённых XYZ.
