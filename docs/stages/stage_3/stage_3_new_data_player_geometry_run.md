Дата: 2026-09-20. Этап 3, визуализация уже реализованных кривой оси и габарита.

## Результат

В локальном каталоге включено отображение `new_data`: AutoRails строит `CurveRailAxis` из текущих пар рельсов, плеер рисует ось, опоры и sweep неизменённого reference-профиля, а слой пересечений показывает все возвраты внутри габарита и его отступов. Это геометрические кандидаты без классификации объекта.

`UNKNOWN` не является меткой каждого объекта или всего датасета. Он остаётся только диагностикой недоступной геометрии конкретного кадра: без опоры рельсов нельзя построить габарит. Например, на frame 1054 пар нет; на 1050 ось есть. Отсутствие пересечений отображается как отсутствие пересечений, но не как вывод «путь свободен».

## Изменения

- `scripts/serve_stage_2_catalog.py` читает только уже существующий `ASSUMED_HACKATHON` contract из `geometry_new_data_experiment.yaml`, проверяет source identity и публикует его reference-профиль в manifest `new_data`.
- Manifest включает geometry only для experimental frame-local отображения, сохраняет `safety_decision_permitted: false` и добавляет заметное предупреждение о допущениях.
- `web/stage_2_raw_player.html` показывает это предупреждение; `web/stage_2_review_layers.js` называет результат геометрическими кандидатами и не акцентирует `UNKNOWN` при построенном габарите.
- Для `new_data` выключен слой «Объектные кандидаты — весь поисковый участок»: он шире габарита и смешивает инфраструктуру с нужными пересечениями.
- В боковой панели добавлена легенда цветов и `м*`: расстояние — прямая от датчика до ближайшего возврата в source XYZ, не путь по оси и не класс объекта.
- Подписи шкалы оси сделаны прозрачными цифрами без фоновых плашек; их расстояние — по оси в `м*`.

Не изменялись raw TAR/bag, профиль, margin, пороги, AutoRails/CurveRailAxis, TF/extrinsics, deskew, карта, tracking, TTC, ROS2 и решение о безопасности.

## Слои

| Слой на снимке | Решение для new_data | Причина |
|---|---|---|
| Ось и опоры рельсов; уровень рельсов | Включить | Объясняет, откуда построена кривая. |
| Габарит; пересечения текущего габарита | Включить | Основной результат задачи: все наблюдаемые возвраты в габарите. |
| Габарит с отступами | Оставить выключенным по умолчанию | Полезен для разбора границы, но делает сцену шумнее. |
| Показывать только внутри габарита | Выключить | Скрывает контекст сцены и точки вне поддержанной оси. |
| Отметки, измерения, ручные 4 точки рельсов | Оставить как инструмент разбора | Нужны для исследования отдельных кадров, не для автоматического результата. |
| Объектные кандидаты по всему участку | Отключить для new_data | Не являются пересечениями габарита и добавляют инфраструктуру. |
| Архив Stage 3, выступы, повторяемость; рамки групп | Удалены из плеера | Старые или отладочные слои не относятся к текущим пересечениям габарита. |
| Раскраска кластеров и её параметры | Удалены из плеера | Связность не определяет факт пересечения; все точки габарита показываются напрямую. |

## Safety и validation review

Проверки текущим агентом после изменения, не независимые. `PASS_WITH_RISKS`, L1 для manifest, UI-тестов и двух прочитанных кадров.

Сохраняются: отсутствие semantic-классификации; все пересечения — кандидаты; без пар габарит кадра недоступен; нет `CLEAR` и решения о свободности; raw не меняется. Непроверены качество, ложные срабатывания от инфраструктуры, низкое реальное препятствие, поведение на полном повороте и browser performance. Следующий минимальный тест — визуально проверить кадры 1050 и 1054 в браузере, затем разметить сценарии для измерения кандидатов, не меняя пороги заранее.
