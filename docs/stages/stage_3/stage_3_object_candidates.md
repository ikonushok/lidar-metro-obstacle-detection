## Спецификация

- Пользователь подтвердил два человека как помехи и согласовал реализацию независимого от отметок детектора с последующим переходом к первым измерениям.
- Цель: отдельные автоматические группы около двух исходных пользовательских точек; расстояние по реальному возврату; все остальные срабатывания видимы.
- Режим: дополнительная покадровая сегментация, не замена safety envelope и не классификатор людей. Этап 3, затем development-проверка этапа 4.
- Источники: src/stage_3_baseline.py (существующая дополнительная above-floor сегментация), config/geometry_contract.yaml, исходные XYZ doubleT_obstacle; Hesai Pandar128 подтверждён docs/README_LiDAR_Specifications.md.
- Вход детектора: только raw XYZ, явная конфигурация, frame identity. Разметка читается только evaluator-ом. Никаких индексов кадров/координат людей в алгоритме.
- Метод: оценка линейного уровня пола по ближним сечениям; дополнительные above-floor компоненты в отдельной поисковой полосе. Параметры исходного прототипа: quantile .1, сечение 10 м, опоры 0–60 м / X +/-1.8, минимум 200 точек/сечение и 4 сечения; grade <=.1, residual <=.4; высота .35–2.8; voxel .2; минимум 5 точек; горизонтальный размер <=3 м. Поисковая полоса X +/-1.9, глубина 0–200 — отдельное demo-допущение из исходного reference-профиля и отступов, не доказанный путь.
- Группы, пересекающие границу поисковой полосы, помечаются потенциально обрезанными. Их bounds — границы возвратов, не полный объём объекта.
- Не удалять исходные точки или существующие низкие/core предупреждения: above-floor ветка дополнительная, отсутствие её результата не CLEAR. Прежняя ось/габарит/UNKNOWN неизменны; вне поддержанного интервала принадлежность габариту UNKNOWN.
- Без карты, accumulation, deskew, tracking. Системы XYZ и времени не меняются; расстояние от начала frame лидара, не от носа поезда.
- Файлы: новый web/stage_3_objects.js и JSON config; подключение в текущие web HTML/review и launcher; tests/test_object_candidates.cjs, tests/replay_object_candidates.cjs; отчёт и артефакты stage_3/object_candidates. Исходный geometry_contract и архивные results/manifest не перезаписывать.
- Проверки: синтетика (unknown/no support, low signal сохраняется в baseline, identity/raw bytes, разные положения объектов); кадры 55/160; развитие на 0/55/100/160/200, затем полная запись. Метрика первоначально exact source anchor -> component, не object/event recall. Для event recall ещё нужны интервалы видимости/объёмы объектов, FP/мин — проверенные отрицательные интервалы.
- Safety-review и затем validation выполняются отдельными проходами текущего агента. Цель L1 + browser smoke; ROS2 backend новой ветки отдельно не заявляется.
- Stop: если два объекта не выделяются без координатных исключений, фиксировать неуспех; не подгонять правила под frame index.

## Evidence до реализации

В архивных protrusion_clusters кадра 55 есть группа 119 возвратов с ближайшим расстоянием 56.140 м; кадра 160 — 1641 возврат, 3.668 м. Обе AABB содержат пользовательские anchors. Это только зацепка, не новая runtime-проверка. В локальном bundled Python отсутствует yaml; существующий серверный Docker image содержит старый код без protrusion_clusters. Новая ветка будет исполняться одинаковым JS в Node и browser без установки зависимостей.

## Результат реализации и safety-review

Добавлены stage_3_objects.js и отдельная JSON-конфигурация, подключены бирюзовые рамки, перечень всех кандидатов, расстояния и экспорт в текущем плеере. Номера групп действуют только в одном кадре. При ошибке результат сбрасывается. Входные XYZ не меняются; дополнительная сегментация не подавляет существующие низкие/core пересечения. Невалидный вход/пол/конфигурация не дают CLEAR. Габарит и его поддержанный интервал не расширялись.

Safety-review текущим агентом отдельным проходом: PASS_WITH_RISKS для дополнительной демонстрационной ветки. Линейный пол и фиксированная поисковая полоса — допущения; группа ближнего человека касается границы полосы. Полнота объекта и принадлежность обоих людей доверенному габариту не доказаны. Слияния с инфраструктурой, низкие и крупные предметы требуют отдельной оценки; это не классификатор людей.
