- Режим: patch существующего пакета; новые роли не добавлять.
- Цель: согласовать AGENTS.md и пять файлов agents с ТЗ, обновлённой методологией, планом и аудитом.
- Источники: docs/hackathon_documentations/5. ДепТранспорта.pdf (разделы 3–8), docs/methodology.md, docs/work_plan.md, docs/dataset_audit.md; изученные ранее schema/topics/counts и 12 облаков.
- Окружение результата проекта: Ubuntu 22.04 + ROS 2 Humble + Docker; данная задача меняет только Markdown.
- Входы: конкретный bag/интервал не обрабатывается повторно; выводы аудита сохраняют границы выборки. Геометрия и связь часов не назначаются.
- Разрешённые файлы: AGENTS.md, agents/*.md, этот экземпляр спецификации. README/методология/данные/зависимости не изменяются.
- Основная роль: текущий агент с agent-pack-designer; последовательные проходы проверки safety и validation, без новых агентов.
- Контракты: обязательства ТЗ отделить от фактической реализации; UNKNOWN, target <- source, запрет автоматического доверия фону сохранить.
- Deliverables: источники требований, маршруты Docker/аудита/сдачи, условия TF/deskew, входные варианты и часы, полный список материалов сдачи, место экземпляров task spec.
- Validation target: L2 только для согласованности пакета; runtime не заявляется.
- Проверки: установленный validate_pack.py --profile generated-pack; git diff --check; ручные сценарии маршрутизации Docker, геометрических порогов, метрик и сдачи; ссылки на существующие документы.
- Acceptance: все шесть исходных файлов обновлены без новых ролей, обязательные и дополнительные результаты покрыты, реализация/safety/evidence не смешаны.
- Stop: не выдумывать результаты Docker/replay, не менять численные пороги или зависимости.

## Результат проверки

- Изменены AGENTS.md и все пять существующих файлов agents; новых ролей нет. Наблюдения о данных не размножались: инструкции ссылаются на docs/dataset_audit.md, несколько известных различий оставлены как триггеры проверки входа.
- Установленный `validate_pack.py --profile generated-pack .`: первый запуск FAIL из-за обязательных буквальных полей `Current validation level:` и `Commands run:`. Поля восстановлены без дублирования; повторный запуск — `PASS L2`.
- `git diff --check` — успешно; проверка существования ТЗ, методологии, плана, аудита и экземпляра задачи — PASS; число файлов agents осталось 5.
- Ручные сценарии маршрутизации: Docker → primary + validation; изменение cluster radius → primary + safety, затем validation метрик; audit-only → primary без обязательного reviewer; сдача → primary + validation с явным покрытием видео/README/экспериментов. Пересечение триггеров разрешено последовательностью этапов.
- Проверка границ: локальный валидный frame без TF не считается отказом; отсутствующий необходимый transform/габарит даёт UNKNOWN; timestamps без движения не разрешают deskew; обучение на единственном положительном bag не даёт независимого test recall.
- Уровень доказательств: L2 для структуры и согласованности инструкций плюс ручной обзор покрытия. Реальная реализация задачи агентами, Docker/replay и качество детектора не проверялись; независимого review другим агентом не было.
- Остаточный риск: оси, единицы, extrinsics и связь часов ещё требуют подтверждения на данных. Следующий минимальный runtime-шаг — отдельная задача Docker Humble с чтением обычного и obstacle bag.
