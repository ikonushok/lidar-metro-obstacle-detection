# Hesai Pandar128: характеристики для lidar_MosMetro3D

Статус: паспортная инженерная справка, не конфигурация runtime и не результат испытаний детектора. Внешние источники не перепроверялись при правке документации 2026-09-23. [Текущий алгоритм](README_methodology.md), [калибровочные ограничения](README_train_clearance.md), [наблюдения по данным](README_dataset_audit.md).

## Статус источников

В проекте применяется **Hesai Pandar128** — 128-канальный механический 3D-лидар. Это утверждение подтверждено владельцем проекта 18 сентября 2026 года. Приведённые ниже паспортные значения взяты с официальной страницы производителя; Hesai отмечает, что это типичные значения, зависящие от версии изделия, firmware и условий применения.

Основной источник: [Hesai Pandar128 — official product page](https://www.hesaitech.com/product/pandar128/).
Дополнительные файлы производителя: [страница загрузок Hesai](https://www.hesaitech.com/downloads/#pandar128) — руководство, файл угловой коррекции и другие материалы доступны после запроса.

## Паспортные характеристики

| Параметр | Значение производителя | Значение для проекта |
|---|---:|---|
| Каналы | 128 | Ожидаются `ring` в диапазоне 0–127; это согласуется с исследованными облаками. |
| Поле зрения | 360° (H) × 40° (V) | Монтаж и фактическая зона обзора определяют, какая часть поля зрения покрывает путь и safety envelope. |
| Угловое разрешение | 0,1° (H) × 0,125° (V) | Основа для distance-aware обработки; не следует выбирать единый радиус кластеризации для всех дальностей. |
| Горизонтальное разрешение при 10 Гц | 0,1° | Частота вращения/публикации должна быть проверена по фактической записи, а не выведена из этой строки. |
| Дальность измерения | 200 м при отражательности цели 10% | Это **не** подтверждённая дальность детекции нашего алгоритма и не гарантия видимости любого препятствия. |
| Плотность точек | 3 456 000 точек/с, single return; 6 912 000 точек/с, dual return | Нужна для оценки нагрузки и возможной потери кадров. Фактическое наличие типа возврата надо проверять в `PointCloud2`. |
| Габариты | Ø116 × 123,7 мм | Полезно только для механического размещения, не для алгоритма. |
| Защита | IP6K7 и IP6K9K | Релевантно подбору оборудования; не доказывает пригодность всей системы к эксплуатации в метро. |
| Лазерная безопасность | Class 1 eye safety | Характеристика датчика, а не системная safety-оценка решения. |
| Заявленный ресурс | более 30 000 ч, typical | Паспортная оценка производителя; не является результатом наших испытаний. |

## Что это меняет в алгоритме

При угловых шагах Pandar128 линейный интервал между соседними направлениями лучей примерно равен

\[
s(r, \Delta\theta) \approx r\tan(\Delta\theta).
\]

| Дальность | Горизонтальный шаг 0,1° | Вертикальный шаг 0,125° |
|---:|---:|---:|
| 50 м | ~8,7 см | ~10,9 см |
| 100 м | ~17,5 см | ~21,8 см |
| 200 м | ~34,9 см | ~43,6 см |

Следствия:

- Для дальних и низких препятствий число точек на объекте может резко снижаться; параметры voxelization, `cluster_radius` и `min_points` калибруются по диапазонам дальности.
- 200 м — физическая заявка на измерение слабоконтрастной цели, а не достаточное условие обнаружения. Нужны раздельные измерения дальности первого и устойчивого обнаружения, recall и FP/мин.
- Файл угловой коррекции производителя требуется сохранять вместе с версией датчика. Нельзя заменять им внешнюю калибровку `base_link <- lidar` или геометрию габарита.
- Per-point timestamps могут быть использованы для deskew лишь совместно с проверенной оценкой движения и согласованной временной базой. В исследованном архиве нет `/tf`, IMU и одометрии, поэтому deskew по умолчанию выключен.

## Сопоставление с текущими входами

В исследованных сообщениях `sensor_msgs/msg/PointCloud2` есть поля `x`, `y`, `z`, `intensity`, `ring`, `timestamp`; `ring` принимает значения 0–127. Это согласуется с 128-канальным датчиком, но формат сообщения сам по себе не фиксирует:

- версию firmware и файлы `angle correction` / `firetime correction`;
- тип возврата (single или dual);
- extrinsics, единицы и направление осей;
- связь bag, header и per-point временных шкал;
- положение лидара на поезде и его перекрытие с safety envelope.

Декодер обязан читать реальные `offset`, `datatype`, `count`, `is_bigendian`, `point_step` и `row_step`, а не полагаться на паспортный формат датчика. Подробные наблюдения по текущему набору: [dataset_audit.md](README_dataset_audit.md).

## Необходимые артефакты для воспроизводимой конфигурации

Перед включением коррекций, deskew или жёсткой геометрии в runtime нужно получить и версионировать:

1. Серийный номер, hardware/firmware версию Pandar128 и режим single/dual return.
2. Актуальные `angle correction` и, если применимо, `firetime correction` файлы именно для этого экземпляра.
3. Калибровку `base_link <- lidar`, единицы, оси и монтажную позу.
4. Источник движения и проверенную связь временных шкал — только если планируется deskew или накопление кадров.

До этого паспортные характеристики служат инженерной гипотезой для проектирования и проверки, но не калибровкой и не доказательством качества детектора.
