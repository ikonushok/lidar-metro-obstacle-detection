## Первая серия: три наиболее конкретные проверки

### B01 — P1: повторный учёт filter time, lean не изолирует заявленный путь

**Класс: direct code contradiction.** `src/cpp/curve_pipeline_stream_cli.cpp:153,209–260`. Код последовательно делает raw analysis, legacy filter, model filter, оба wireframe; затем `common_elapsed = now - started`; затем `legacy_processing_ms = common_elapsed + legacy_filter_ms` и `model_processing_ms = common_elapsed + model_filter_ms`. Получается:

```text
common_elapsed = common_work + legacy_filter + model_filter + wireframe
model_processing_ms = common_elapsed + model_filter
legacy_processing_ms = common_elapsed + legacy_filter
```

Выбранный фильтр учтён дважды, чужой фильтр не исключён. Ветка `if (lean_benchmark)` расположена после этих вычислений. Она уменьшает JSON, но не убирает предшествующие вычисления. Это противоречит `README_noise_classifier.md`, где lean описан как один production-like model path без wireframe и больших debug arrays.

Влияние: текущие `processing_ms` нельзя интерпретировать как runtime одного метода. Не установлено, что сохранённые раньше p95 рассчитаны именно этой ревизией; не пересчитывать их вычитанием p95 разных стадий, поскольку квантили неаддитивны.

Минимальная следующая проверка: на одном фиксированном кадре сохранить wall timer и непересекающиеся intervals для decode/axis/envelope/legacy/model/wireframe/serialize; убедиться, что lean выполняет только заявленный путь. После отдельно согласованного изменения — одинаковый длинный replay и новый versioned benchmark.

### B02 — P1: unit gate требует незапущенный HTTP integration server

**Класс: reproduced environment failure + static lifecycle contradiction.** `tests/test_dataset_catalog_http.py:9–13` использует `http://localhost:8080`, без создания fixture. `scripts/validate_stage_3.ps1:15` запускает общий unittest discovery, но сервер до него не запускается. Новый local discovery дал три `ConnectionRefusedError/URLError`; дополнительно Windows не импортирует ROS `rclpy` для другого test module.

Влияние: обещанная README команда проверки не может считаться воспроизводимо зелёной только по старому отчёту. Windows rclpy absence не объявляется дефектом Humble-контейнера. Текущий Docker script целиком не запускался, поэтому ему не приписывается новый фактический failure.

Минимальная следующая проверка: разделить команды unit и integration, явно задавать server/port, проверить запуск из чистого образа. Исправление tests/launcher — отдельная задача; простое исключение всех падающих тестов не доказывает исправление integration.

### B03 — P1: Python CLI `--geometry-config` не используется в обычном запуске

**Класс: direct code contradiction, без ROS воспроизведения.** `src/stage_3_baseline.py:585–593` парсит аргумент и использует только с `--print-contract`. Обычный путь вызывает `run_node()` без аргумента (`:573–578`), который создаёт `baseline_node_class()()`; конструктор `:538–546` выбирает default или ROS parameter.

Триггер: запуск модуля с отдельным `--geometry-config <path>` без `--print-contract` и без `--ros-args -p geometry_config:=...`. Следствие: ожидаемый CLI path не попадает в node. Это не утверждение, что сломан ROS parameter или callers, передающие config напрямую.

Минимальная следующая проверка: существующий entrypoint с двумя различимыми валидными конфигами; наблюдать реально выбранный путь конструктора/результат. Не менять контракт по догадке; после теста — адресная передача аргумента и проверка ROS override precedence.

## Не называть доказанными багами

- Подавление низких/малых raw CORE — **подтверждённое поведение** фильтров, которое расходится со старым планом. Был ли это ошибочный или намеренный product choice, нельзя решить ревизией. Нужны актуальный signal contract и тест low/small regression, прежде чем заявлять safety-эффект.
- Два события в старом registry против positive 13–64 у trainer — **конфликт определения ground truth/scope**, не доказательство физического нахождения OBS-003 внутри envelope.
- arc_clamped может потерять дальние пересечения, но хуже/лучше текущего tangent на новых данных этой ревизией не измерялось. Результаты старого stage report — исторические, не новый replay.
- Старые JS lifecycle и floating equality failures не объявляются текущими: новый Node suite прошёл; соответствующие Python pure checks также прошли.
