## Backlog, не смешиваемый с доказанными багами

- **B04 / P2 — задержка stale request:** чтение/extraction выполняется до token-check, in-flight C++ не отменяется, cache=3. Это достижимый код ожидания, но его вклад в жалобу пользователя сейчас не измерен. Следующий опыт: cold/warm один кадр, смена SQLite-части, быстрый seek; измерить lock wait/queue age/extract/decode/compute/JSON/XYZF/render. Не называть очередью DDS.
- **B05 / P2 — rebuild без замены контейнера:** после build launcher возвращает совпадающий running container. Команда пользователя предварительно останавливает порт и избегает сценария; не считать причиной текущего запуска. Узкая будущая проверка: image id процесса до/после RebuildImage без stop.
- **B06 / P2 — default fmin 3 против 2:** direct constructor=3, launcher/node=2. Пункт 2 корректен, потому что передаёт 2 явно. Унифицировать только в отдельной минимальной правке и проверить всех callers.
- **B07 / P2 — version provenance:** model JSON есть в Git, но C++ использует встроенные пороги; новые JSON после переобучения автоматически runtime не меняют. Нужны проверка parity экспорт→C++, model hash и image id в evidence. Сейчас показанное дерево и текущие константы совпадают; drift не доказан.

Не считать багами: отдельный ROS2 вход, наличие экспериментальной дуги в C++, UNKNOWN вместо CLEAR и отсутствие независимого positive test. Последнее — ограничение оценки, а не исправляемый строкой кода дефект. Возможность пропуска низкого объекта моделью следует измерять как алгоритмический риск, не устранять произвольным снижением threshold.
