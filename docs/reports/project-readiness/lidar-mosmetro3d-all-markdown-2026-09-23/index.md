Дата: 2026-09-23. Проект: lidar_MosMetro3D. Категория: project-readiness; режим docs-vs-code. Исходное состояние сохранено коммитом **4d5bb30**. Это новая ревизия по исходникам, а не продолжение выводов старого аудита.

**Документация в целом не соответствует текущему запуску.** Рабочая цепочка реализована: архив bag → XYZ → прямой C++ → поиск рельсов → tangent-габарит → CORE-компоненты → model_v1 → JSON → плеер. Отдельный ROS2-вход использует то же ядро и модель; заказчик может запускать его без плеера. Проект остаётся экспериментальным candidate-only решением: работоспособность интерфейса не доказывает качество на новых проездах или готовность к эксплуатации.

Главная проблема документов — смешение текущих инструкций, предыдущих алгоритмов, исследовательских планов и результатов разных версий. YOLO11m — отдельный нерелевантный материал, который следует убрать из главного README. Напротив, arc/CUDA/одометрия/синтетика относятся к исследованиям проекта, но не входят в данный запуск.

## Запуск пользователя

Команда корректно выбирает текущий путь; `NoiseFilterMode=model_v1` и `RailSelectionMethod=development_candidate` берутся по умолчанию. Явная запись параметров удобнее для воспроизводимости:

```powershell
docker ps -q --filter "publish=8100" | ForEach-Object { docker stop $_ }
.\scripts\run_stage_2_cpu_player.ps1 `
  -Port 8100 `
  -RailSelectionMethod development_candidate `
  -RailForwardMinM 2 `
  -ForwardExtensionMethod tangent `
  -NoiseFilterMode model_v1 `
  -RebuildImage
```

Открыть `http://localhost:8100/`. Нужны Docker Desktop, оба локальных архива и подготовленные viewer/DDS-файлы: **`-RebuildImage` не подготавливает эти локальные данные и assets**. Подробнее — в отчёте о коде. Здесь запуск не повторялся, работающий сервер не останавливался.

## Ближайшее решение

Сначала синхронизировать активные документы, затем исправить измерение времени и проверить причины ожидания кадров. Продолжать доработку алгоритма по наблюдаемым ошибкам; пользователь уже подтвердил регрессию tangent и положительный интервал **13–64 включительно**. Не ставить повтор этих действий условием завершения документации. Финальное видео и фиксация версии — после доработки алгоритма.

Вердикт: **UPDATE_REQUIRED** для документации; **HOLD** для общих quality/release claims. Проверка доказательств проведена отдельным проходом тем же агентом по `agents/validation_reviewer.md`, без заявления независимого review.
