Статус: запуск восстановлен; первопричина недоступности NTFS-сокетов не установлена. Исправление кода Docker не выполнялось.

## Наблюдаемое поведение

Docker Desktop 4.78.0 (229452), Windows: запуск Linux Engine завершался ошибкой `initializing Inference manager` / `dockerInference` / `The file cannot be accessed by the system`. Ошибка подтверждена скриншотом пользователя и `com.docker.backend.exe.log`. `docker version` возвращал только Client; серверный named pipe отсутствовал.

Файл `%LOCALAPPDATA%/Docker/run/dockerInference` имел длину 0, атрибут ReparsePoint и старую дату изменения 2026-06-24. `fsutil reparsepoint query` вернул ERROR_CANT_ACCESS_FILE (1920). Это согласуется с [сообщением Docker #448](https://github.com/docker/desktop-feedback/issues/448), но не доказывает локальный механизм возникновения повреждения.

## Согласованные действия и результаты

Пользователь отдельно согласовал восстановление Docker и через запросы повышения прав — переименование служебных папок. Сброс, переустановка, удаление образов, volumes и WSL-диска не выполнялись.

1. Остановлены процессы Docker Desktop/backend/build и только WSL-дистрибутив `docker-desktop`.
2. Попытка Rename-Item самого dockerInference не удалась: ошибка доступа сохранилась.
3. Папка `%LOCALAPPDATA%/Docker/run` переименована в `run.stale-20260918`. Новый запуск прошёл этот этап, но остановился на `%LOCALAPPDATA%/docker-secrets-engine/engine.sock`.
4. Папка docker-secrets-engine содержала только нулевой engine.sock; сохранена под именем `docker-secrets-engine.stale-20260918`.
5. Неудачный промежуточный запуск оставил новый недоступный dockerInference. Обе текущие служебные папки, если существовали, сохранены с суффиксом `.stale-20260918-2` перед следующим запуском.
6. После одновременного восстановления `docker version` успешно показал Server Docker Desktop 4.78.0, Engine 29.5.3, linux/amd64. `docker ps -a` успешно вернул пустой список. Последующая сборка контейнера проекта также завершилась успешно.

Не заявляется исправление внутреннего дефекта Docker или гарантия отсутствия повторения. Резервные папки сохранены; удалять их для выполнения задачи не требуется.
