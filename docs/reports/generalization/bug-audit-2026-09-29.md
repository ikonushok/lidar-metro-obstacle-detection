# Кандидаты дефектов и следующие проверки

Дата: 2026-09-29. Тип bug-audit; режим статический; категория generalization; проект lidar-metro-obstacle-detection. L0. NO_RUNTIME_BUG_PROVEN: воспроизведение не выполнялось. Ниже поведение, доказуемое кодом, отделено от кандидатов нарушения целевого контракта.

Карта: общий C++ detector → direct/ROS2 temporal wrappers → evaluator с frame/event labels. Стадия: prototype. Цель: выделить риски, влияющие на переносимость, без изменения алгоритма.

## Приоритетная тройка
1. **P1, кандидат геометрического FN.** curve_envelope_core.cpp:241–246,904–960: boundary действует на уже выбранные CORE-компоненты и имеет приоритет даже над >=1000 точками. Например широкая высокая компонента с centroid_z>1 может быть физическим внутренним препятствием, но уйти в warning. Проверка абсолютного X слева не симметрична и не привязана к rail-local coordinate. Доказано условие подавления; физический FN ещё не воспроизведён. Минимальный тест после согласования: фиксированная валидная ось, полностью внутренний объёмный объект, его перенос/зеркальная пара, проверка raw CORE и public alarm.
2. **P1 для интерпретации качества, прямое расхождение разметки.** config/evaluation_labels.json:18 говорит obj09 ambiguous_excluded; :85 включает его в positive_events, evaluator считает окно. Минимальная проверка: независимая локализация obj09 и решение, что оценивается. До разрешения не трактовать 6/6 как verified object recall.
3. **P2, кандидат ложного temporal-подтверждения.** CLI:363–385, ROS2:176–258 подтверждают общие frame-level bool без object association. Разные компоненты в соседних кадрах могут подтвердить общий alarm. Минимальный тест после согласования: разные несвязанные компоненты по одному кадру, затем один стабильный объект; сравнить confirmation. Это ограничение текущего дизайна, не воспроизведённый полевой FP.

## Backlog оценки
- Event-window TP без spatial matching и без FP вне окон завышает силу вывода, если назвать его object-quality (evaluator:140–175). Для заявленной оконной метрики поведение намеренное.
- totals смешивает frame и event единицы (evaluator:250–258). Не использовать для агрегированного precision/recall.
- UNKNOWN без true становится TN на negative (detector_alarm/add); отдельно измерять availability. Это не нарушение runtime UNKNOWN!=CLEAR, но потенциально неверная интерпретация TN.
- Политика JSON и EVALUATION_METRICS отстают от public early-ветки C++; нужна привязка документации и результатов к версии.

Новые repro-файлы/тесты не создавались; production не менялся. Команды: Get-Content, rg -n, git status/rev-parse (полный контекст в index.md); результаты — статические цепочки выше. Не проверены фактическая частота кандидатов на реальных данных, pipeline latency и контейнер. Остаточный риск: возможны дополнительные FN/FP вне изученного scope. Следующий минимальный шаг: разрешить разметку obj09; затем согласовать узкие геометрические/temporal repro, не калибровать detector по скрытому тесту.
